# LIBERO — 湯沸かし訓練

学園祭のコーヒー店舗で、最大5台の電気ケトルを管理するリベロ役の3Dトレーニングゲームです。難易度は `EASY`（2台・3人）、`NORMAL`（3台・4人）、`HARD`（4台・5人）、`DEATH MARCH`（5台・6人）の4段階です。さらに `MORNING`、`LUNCH`、`AFTERNOON`、`CLOSING` の時間帯を選択でき、注文間隔と3D空間の光色が変化します。

8個の共有コーヒーポットのキュー内から先頭の空ポットを自動取得し、900ml・92°C以上のお湯を届けます。キュー先頭に戻り湯入りポットが残っていても提供は継続できます。返却ポットには少し冷めた湯が400〜500ml残るため、戻り湯回収はキュー先頭に対して行います。

コーヒーポットの3Dモデルは、鏡面ステンレスの円錐台形ボディ、ドーム形のフタ、極細のS字注ぎ口、大きな金属製ループハンドルを持つドリップポット形状です。

給水はボタンまたは `F` キーを押している間、毎秒約250mlの速さで進みます。加熱出力は一定で、温度上昇速度はケトル内の水量に反比例します。

加熱停止後の電気ケトルは、毎秒約0.25°Cの割合で緩やかに冷めます。

注文待ちは `ON TIME`、`DELAYED`、`CRITICAL`、`OVERDUE` の4段階です。時間帯ごとの基準時間は以下のとおりで、注文ごとに全区間へ±10%のランダム補正が入ります。時間切れの注文は消えず、`OVERDUE` のまま提供されるまで保持されます。難易度はケトル数とドリッパー数だけを変更します。

| 時間帯 | ON TIME | DELAYED | CRITICAL | OVERDUE到達 |
| --- | ---: | ---: | ---: | ---: |
| MORNING | 26秒 | 18秒 | 12秒 | 56秒 |
| LUNCH | 11秒 | 8秒 | 6秒 | 25秒 |
| AFTERNOON | 20秒 | 14秒 | 10秒 | 44秒 |
| CLOSING | 15秒 | 11秒 | 8秒 | 34秒 |

画面上の達成度は注文単位の評価です。提供時の状態を `ON TIME=100%`、`DELAYED=70%`、`CRITICAL=30%`、`OVERDUE=0%` として平均します。未提供の注文はON TIMEの猶予を過ぎたら0%で評価対象に入ります。猶予中は評価保留とし、終了直前に来た注文でも猶予切れまでは不利に扱いません。評価対象がなければ「未評価」です。提供済みの評価は確定し、待機時間だけで回復することはありません。最終達成度95%以上でランクS、85%以上でA、70%以上でBとなります。ランクは丸め前の値で判定し、結果画面に評価件数・未提供件数・提供時の状態別件数を表示します。

給湯時には、定刻かつ96°C以上で `PERFECT`、超過直前なら `JUST IN TIME`、最後の超過注文を解消すると `RECOVERY` が表示されます。時間超過前の連続提供でCHAINが育ち、3回で `FLOW!`、5回で `UNSTOPPABLE`、10回ごとに `LEGENDARY` を演出します。時間超過と空焚き・低温での給湯試行でCHAINがリセットされます。演出は達成度や機器性能を変えません。

給湯の軌跡、短い効果音、沸き上がり通知、結果のカウントアップを追加しています。右上の `FX` と `♪` で動きと音を個別に切り替えられ、OSの「視差効果を減らす」設定にも対応します。

## ローカル実行

Three.js 0.170.0 は `vendor/` に同梱しており、起動時に外部CDNへ接続する必要はありません。ライセンスは `vendor/three.LICENSE` にあります。難易度・時間帯の選択は3D描画の初期化から独立しているため、準備中も選択できます。選択中の設定は3D描画の準備後とシフト開始時に引き継がれます。

ES Modulesを利用するため、任意の静的HTTPサーバーで配信してください。

```bash
python3 -m http.server 3000 --bind 127.0.0.1
```

## ビルド

```bash
npm run build
```
